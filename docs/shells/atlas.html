dcli Shell Atlas

Nine Hyprland desktop shells live side by side on one CachyOS machine and swap at runtime — no relogin, no package churn. This page maps each one: where it is installed, where its configs live, how it launches, and how it updates.

switch-shell.sh <name>writes the shell name, kills every running shell, reloads Hyprland, launches the pick (no arg = fuzzel picker)
→
shells/active.confa bare shell name — the single switch the whole system pivots on
→
hypr/hyprland.luareads active.conf and dofile()s that shell's Lua config from its shell_paths table
→
the shell processstarted by the script itself (exec-once never re-fires on reload), guarded by pgrep
The one rule that breaks everything: exactly one Quickshell provider may be installed. Every packaged fork declares Conflicts=quickshell. The provider here is quickshell-git (module shells-quickshell-git) — it provides quickshell, so all Quickshell-based shells resolve and run under it. Swap providers only with scripts/switch-quickshell.sh, never by enabling modules by hand.

The nine shells

caelestia

custom forkcaelestia shell -d

Fork of caelestia-dots/shell, and the most maintenance-heavy shell here: it is the only one whose C++ plugin is compiled locally, and that plugin is the source of every serious breakage so far. Hard-requires the quickshell-git provider.

Source
~/Projects/shell/real — origin plusdrag11/caelestia, branch my-caelestia-rebased (the fork's default branch is a plain upstream mirror; the branch must be pinned)
Installed QML
~/.config/quickshell/caelestia (overrides the package's /etc/xdg copy)
C++ plugin
~/.local/lib/qt6/qml/{Caelestia,M3Shapes} (overrides the package's /usr/lib copy)
Config
~/.config/caelestia → the fork's caelestia-configs (version-controlled inside the fork, not in dcli)
Hyprland
~/.local/share/caelestia/hypr/hyprland.lua — supplied by the checkout, not this repo
Update
no script on purpose — 32 local commits mean a real rebase, rebuild, and verify
  • trapCMake target must stay qml_module(caelestia-core — a rebase reverted it once and Qt aborted with "Cannot add multiple registrations".
  • trapStale .so files survive cmake --install and shadow fresh builds ("ButtonRow is not a type").

ambxst

custom forkambxst

Fork of Axenide/Ambxst. Quickshell-based but installed by the fork's own install.sh, which writes the launcher to /usr/local/bin/ambxst — the one shell binary that is neither pacman's nor dcli's.

Source
~/.local/src/ambxst — origin plusdrag11/Ambxst, branch my-ambxst
Runtime link
~/.local/share/ambxst → the checkout (where its hyprland.lua loads from)
Config
~/.config/ambxst → dotfiles/ambxst — dcli-managed: binds.json, config/, presets/
Hyprland
its own hyprland.lua from the checkout, then dotfiles/hypr/shells/ambxst-overrides.lua layered on top (monitor scale, us,ara layout, pointer accel)
Update

omarchy — Quattro

DHH's Hyprland desktop at v4.0 "Quattro" (RC), run as a shell, not a distribution: one long-running Quickshell process hosts bar, menu, notifications, OSDs, panels, lock screen and polkit agent as plugins. Its whole-distro install.sh is never run — setup-omarchy.sh reproduces only the checkout, theme seed, icon font, and state seeds.

Cross-cutting rules

  • Hyprland loads hyprland.conf or hyprland.lua, never both. This machine is all-Lua; under a Lua config hyprctl keyword is rejected — use hyprctl eval 'hl.…'.
  • Two shells bring their own Hyprland config (caelestia, ambxst — from their checkouts); six use standalone configs in this repo; omarchy is the hybrid loader.
  • SUPER+SPACE is reserved everywhere for the us/ara keyboard-layout toggle; launchers live on a Super tap or SUPER+D per shell. SUPER+SHIFT+O is the way out — it opens the shell picker from any shell.
  • Per-shell Hyprland settings GUI: scripts/edit-hypr.sh [shell] retargets HyprMod at the shell's managed overlay, dotfiles/hypr/shells/<name>/hyprmod.lua.
  • Stale processes are the usual "new shell looks broken" cause — anything in pgrep -a -f "qs -c|quickshell|ambxst|dms run|noctalia" that isn't the active shell shouldn't be there.
  • Adding a shell touches four index-aligned things: KNOWN, icon_files, blurbs in switch-shell.sh, and lines= in the fuzzel picker config.
